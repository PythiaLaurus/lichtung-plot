方案撰写基线为 `b6e52a4`；用户在方案评估后明确要求开始实施。
批准范围为本文的计费简化，不恢复额度拒绝，也不恢复后续主题功能迁移。

## 一、已完成的决定与此次提案的边界

最初实施的用户决定是 `3ae46a1`：在 `src/font/canonical.rs` 设置
`ENFORCE_RESOURCE_QUOTAS = false`，由三个集中判断入口关闭七类账本额度拒绝。
该历史步骤仍保留计数、锁、配置字段和分配策略。随后按本文批准边界删除了
计费基础设施；当前执行状态见下文，不再保留该临时开关。

本次建议：**从生产渲染路径移除细粒度统一计费，保留必要的正确性机制，
将少量有用途的指标留在现有测试／基准诊断框架中。**

不增加新的公开预算 API、运行时模式选择、通用监控框架或硬件成本打分公式。
不调整科学数据、字体选择、换行规则、图例顺序、坐标投影和默认绘图外观。
不以“重新低于一百万”作为验收条件。

依据与局限：

- [综合结论](../docs/resource-accounting-review.md)
- [静态审计](../docs/resource-accounting-static-audit.md)
- [实测方法与结果](../docs/resource-accounting-performance.md)
- [原始计时样本](../docs/resource-accounting-measurements.csv)
- [逐操作计数拆解](../docs/resource-accounting-operation-breakdown.md)

计数不是 CPU 指令或内存峰值；已有实测仅覆盖指定主机、字体和负载。
本计划不把漏计都改成新增计费，也不把每个现有额度都包装成一种“保护”。

## 二、七类计费的处置总表

以下“删除”指删除生产计费、额度状态及其专属传播代码；实际数据结构和算法
不会因为其计费被删除而一并删除。

| 当前计费类别 | 建议处置 | 删除内容 | 如需观察，保留什么 |
| --- | --- | --- | --- |
| Processing visits | **删除生产计费** | 字符、字节、列表、碰撞和算术估算混合总分；百万额度；逐步骤申请 | 诊断构建中按语义分别记录输入量、比较、shaping、候选和精化次数，不求总分 |
| Retained planning records | **删除生产计费** | 累计 header／元素／预留槽打分及百万额度 | 实际容器长度、场景图元／字形数量；需要时单独做分配剖析 |
| Measurement/intrinsic calls | **移为诊断指标** | 生产计数、百万额度及只用于申请一次额度的 token | 现有测量／缓存／重测次数，明确不等于所有函数调用 |
| Cache entries | **删除统一计费** | 跨缓存累计插入总分、百万额度及额度专用逻辑 | 具体缓存的命中、未命中、当前条目和替换次数；保留各缓存现有行为策略 |
| Topology slots | **删除额度计费，保留结构** | 跨数据行、单元格、类别等的百万总额度 | 实际拓扑数量、原始行身份、父子映射、共享输入及长度溢出检查 |
| Font discovery entries | **删除额度计费** | 百万发现事件额度及相应生产计数／锁 | 诊断中分别记录配置文件、目录事件、实际字体文件／face 数量 |
| Font/source/scratch bytes | **删除混合计费** | 将文件字节、累计缓冲区请求、估算大整数 scratch 混为一个 512 MiB 额度的逻辑 | 真正的读入长度、容器容量、实际输出长度；内存另测 RSS／活跃堆／累计分配流量 |

最终不保留一个长期返回成功的 `claim_*` 空壳系统。调用方迁移完成后，删除
`ENFORCE_RESOURCE_QUOTAS`、旧额度常量、额度配置、纯计费错误分支和未使用的参数。
先前关闭拒绝的配置仅是历史过渡状态，不是当前 API。

## 三、应删除的具体代码职责

| 对象与主要位置 | 删除范围 | 必须避免误删的内容 |
| --- | --- | --- |
| `font/canonical.rs` 的统一计数器、额度判断和计费锁 | 七类 `claim_*`、仅服务它们的 counters／limits／usage 传播 | 真正的字体缓存同步、已准备字体身份、同一操作的所有权关系 |
| 字体栈与文字查询 | 对逐字节相等、哈希、复制、Arc 共享收取的 visits | 相等比较本身、完整缓存键、不可变共享和字形选择 |
| Unicode 与 shaping 入口 | 各字符／分解节点／断点上的统一额度申请，额度专用回调参数 | Unicode 算法、合法断行、bidi、组合字符、字体覆盖、可失败预留 |
| `data/source.rs` 和各绘图生产者 | 规范化、搜索、排序、投影、统计、避碰的预算单价 | 数据合法性、真实循环、排序顺序、统计结果及其源身份 |
| `theme/spacing.rs`、`numeric.rs`、`theme/color.rs` | `limbs² × operands` 等费用计算及纯计费 scratch 估算 | 精确运算、区间证明、尺寸计算、精度增长的整数溢出检查 |
| 布局、反馈、图例和子缓存 | 查找／相等／反馈记录／重测的额度申请 | 真实输入依赖、循环检测、布局次数规则、选定不可变结果 |
| 几何、捕获和终端输出 | 生产账本 debit 及只为价格准备的数据 | 几何验证、实际大小计数、SVG 保留长度、PNG 格式检查 |
| 旧额度错误与测试专用额度设施 | 无生产用途的 `Limit` 类别、旧测试配额构造／调节辅助方法 | I/O、真实分配失败、数据／字体错误、算术和渲染生命周期错误 |

历史发现的重复收费，例如标签域 `4n` 记录对应 `2n` 元素，不需要先建设一套
新的“正确收费”机制再删除。迁移时直接移除该费用；实际数组保留、容量和内容
继续由它们自己的正确性要求控制。

## 四、应保留的机制——它们不是统一计费

| 机制 | 保留理由／范围 |
| --- | --- |
| 长度、乘积、索引和坐标的 checked arithmetic | 防止不可表示的分配请求、越界和无效几何；不能以关闭计费为由改成截断或饱和 |
| `try_reserve` 等可失败分配和 I/O 错误 | 真实失败仍应返回错误；不宣称能捕获所有第三方分配器 OOM |
| 数据、区间、类别和科学来源验证 | 保留 finite、范围、非零塌缩、完整来源／标签等既有契约 |
| 字体发现与字体文件一致性检查 | 保留规范顺序、已读取字节身份、实际长度检查、坏字体／缺字拒绝 |
| 字体 census 封存、源身份和同一操作归属 | 保证准备、测量和绘制使用同一份科学／字体输入；只移除额度部分 |
| 缓存键、相等检查和不可变共享 | 仍需正确判断是否可以复用；不能为删除比较计数而删除比较 |
| 最多八轮根反馈与循环检测 | 它们定义已批准的布局协调／终止行为，不是 visits 打分 |
| 自动图例的既定边／flow 尝试及次数规则 | 保留确定性顺序和父布局拟合行为；不在计费清理中改成更多搜索 |
| 既有数值算法、候选序列及终止规则 | 保留其数学与行为契约；不是将无关的新次数限制补回计费系统 |
| 合法数据窗口与 required text 的拟合规则 | 数据裁剪和必需文字拒绝继续分别按契约工作 |
| PNG 独立尺寸、像素数和实际 parser 输入检查 | 保留当前每轴 32,768、100,000,000 像素、64 MiB parser 输入政策；本次不修改这些独立输出边界 |
| 可选文字 memo 的 256 条插入策略 | 达到后停止可选缓存而非拒绝渲染；保留其现有行为，后续有性能证据再单独评估 |
| 已冻结场景的重放及输出一致性 | 保留同一选定场景用于 SVG／PNG 的契约，不重新布局 |

公开 exact tick 列表、bootstrap、统计网格等既有输入／算法边界，也不因出现数字
上限就自动视为“资源计费”。按其具体语义保留；若需改动，另列行为提案。

上述算术检查指真实数据与计算。累计 visits、累计收费 bytes 和纯费用公式的
溢出检查及其专用测试随账本删除，不保留无用途的计数器来承载这些错误。

## 五、应修改而非直接删除的对象

| 对象 | 建议修改 |
| --- | --- |
| `OperationGenerationResources`、`OperationFontResources` 及其克隆 | 将真实操作身份、字体环境和 palette/text 等缓存迁到语义明确的操作上下文；删除 counters 部分，不保留误导的“资源预算”命名 |
| `FontBudget` | 拆出仍有用途的归一化缓存／字体准备上下文；没有其他职责的部分直接删除 |
| `PlotData` 的 operation/source context | 继续传递必需的准备身份或缓存依赖；不再为了计费给纯读取函数增加可失败路径 |
| `RowTopologyAdmission` 等 ticket | 保留确有用途的原始输入／操作身份约束，去掉额度和费用。若移除计数后 token 完全没有语义职责，则连同 token 删除 |
| `MeasurementCall` | 当前 token 的职责是证明计费一次；如果没有独立正确性作用，随计费删除，不另造无意义 token |
| 各类 `reserve_*` helper、`PreparedStage`／`FinalStage` | 保留长度检查、可失败分配和真实阶段／冻结边界；删除账本申请。`reserve` 仍可失败，不全部改成 infallible |
| 字体发现预留一百万个 `DiscoveryRecord` | 移除与旧额度绑定的预分配，采用实际前缀驱动的 fallible 增长；保持发现顺序、过滤和文件身份 |
| `Result` 与错误转换层 | 只有在函数失去全部真实失败原因时才去掉 `Result`；仍可能 I/O、分配、算术或拟合失败的函数继续传播错误 |
| Unicode 的 `(bytes, visits)` 回调 | 删除纯计费参数；需要的分配和真实错误以直接接口保留，不让 callback 变成隐藏空记账器 |
| 输出的计数器，如 `CountBuffer` | 保留用于精确预留或 PNG parser 长度判断的实际输出计数；与统一费用账本区分，不删除真正有用途的 count pass |
| 现有 `orchestrator/measurements.rs` 和 benchmark 观察 | 仅保留明确命名的诊断数据；删除对旧“资源总分”的效率判定。不是把所有旧 visits 搬到另一个总分里 |
| 规范与证据文档 | 当前契约明确取消统一计费；历史数据继续标明版本，不改写历史数字，也不称累计估算字节为内存峰值 |

随对应实现同步检查 `05_LAYOUT_SYSTEM.md`、数值／图例专项规范和组件构造
设计中的未来计费要求，避免后续迁移重新引入已删除账本。数值算法的误差界、
收敛证明和精确舍入要求继续保留；删除计费不等于放宽数学正确性。

移除计费不等于移除共享、缓存、哈希或源相等检查。函数签名的简化必须来自
职责真的消失，不能只为了减少参数而丢失必要依赖。

原操作身份依附于计数器 Arc。删除承载身份的计数器前，须先分离独立身份；
克隆仍属于同一操作，新操作必须有不同身份。真实缓存的同步另行保留。
字体发现容器使用可失败的摊销增长，不逐条精确重分配，也不预留旧额度大小。

## 六、诊断指标保留到什么程度

优先使用已有测试／基准构建中的观察框架；普通生产渲染不执行逐字节计费。
不增加公开诊断 API、环境变量模式选择或新的生产 feature 开关。
下表是有需要时的观察选项，不是必须补齐的新指标清单；优先使用已有观察。

| 指标 | 建议保留的意义 | 不应继续声称 |
| --- | --- | --- |
| 整体及阶段耗时 | 固定流程、相同输出的 wall time；注明是否包含字体发现、轮廓或 PNG | 从 visits 推算耗时；相加存在嵌套的阶段 timer |
| CPU 与内存 | 外部 CPU／采样剖析、独立进程 RSS，必要时另测 allocator 流量 | 用累计 `claim_bytes` 替代真实峰值 |
| 文字与 shaping | 调用次数、输入字符量、输出字形量、候选行次数 | 将这些不同单位相加成“资源消耗” |
| 图形准备与复杂算法 | 输入规模、保留图元数、实际碰撞对和数值精化次数 | 认为一次碰撞与一次字符比较等价 |
| 具体缓存 | 命中、未命中、重测、当前条目／替换次数 | 用一个跨缓存累加总数代表占用或正确性 |

已有历史 A/B 对照不能作为清理后的新性能结果。最终比较使用相同原始输入、
字体环境、输出形式和数据，不通过删词、减点、换算法或跳过输出缩短耗时。
主要性能基线是当前已关闭拒绝的版本；旧版本提前拒绝的耗时不是成功渲染耗时。

## 七、建议实施顺序与阶段性交付

**以下步骤已获批准。** 每一步迁移当前调用方并删除旧表示，完成后单独提交。
不恢复已关闭额度，不把所有工作堆到一个最终清理提交中。

| 顺序 | 工作与边界 | 完成标准 |
| --- | --- | --- |
| 文字／字体／查询路径 | 先处理当前 claim 调用最密集的路径；保留 shaping、字体身份、完整缓存键和源语义 | 正常文字路径无细粒度预算申请，选定现有文字／输出行为保持 |
| 数据与图形准备 | 去掉提取、排序、KDE、避碰、映射等单价；保持实际循环和 scientific validation | 科学数据、排序、源 ID、图元内容一致；不出现另一套打分 |
| 主题／布局／捕获 | 去掉精确间距、反馈、测量和捕获费用，保留算法与真实边界 | 布局顺序、默认外观、完整 ink 和冻结重放保持 |
| 删除账本基础设施 | 清除无消费者的 counters、locks、limits、错误、token 和参数；语义上下文单独留存 | 不留下长期 no-op `claim_*`、兼容别名或新预算选择器 |
| 文档与性能收尾 | 更新当前规范和状态；以现有同源负载对照真实耗时、输出和内存 | 报告实际结果与未知项，不以计数降低或低于阈值作为成功 |

跨步骤的暂存应是可编译、职责清晰的单一当前实现。可以逐个资源类别完成
调用迁移后删除对应字段，但不能添加第二个 renderer 或旧／新路线 fallback。
相关测试和当前契约随对应代码同步更新，不积压到最后；最后只汇总一致性和性能证据。
