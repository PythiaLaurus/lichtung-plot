# Resource-accounting removal: verification and comparison

## Implementation boundary

The cleanup removes the seven cumulative accounting classes and their production
fees, quotas, locks, limit errors and accounting-only parameters. It replaces the
remaining resource carriers with `OperationContext`, `FontPreparation` and
`RowSourceContext`, retaining operation/source identity and actual caches.
Pure arithmetic/equality queries no longer return accounting errors; real
allocation, representation, data, font, fit and lifecycle errors still propagate.

The reference is `8c6e011`: quota refusal was already disabled, but accounting was
still present. This is a successful-render comparison baseline, not the older
quota-rejecting revision used in the October 7 experimental study.

## Verification on the local Linux host

The following records the accounting-cleanup checkpoint. Its nine outstanding
integration assertions are addressed by the later user-directed test-policy
change below; the original run results are retained as historical evidence.

* Formatting and strict `cargo clippy --locked --offline --all-targets --
  -D warnings` passed.
* `just docs` passed with rustdoc warnings denied; `just package` built and
  verified the unpacked package successfully.
* Focused font, Unicode/text, exact arithmetic, source identity, palette/text
  cache, geometry, parent feedback, caption and output checks were run during
  migration. Later focused groups included 28 plot/cache/geometry checks and
  seven axis/capture checks, all passing.
* The one broad closure invocation (`just test`) reached the library tests:
  **1340 passed, nine failed, 17 ignored**. Two failures were remaining pure quota
  tests and were removed. The other seven reproduced on `8c6e011`; their stale
  expectations were reconciled and all seven passed in focused reruns. The whole
  library suite was not repeated after those localized changes.
* The remaining 14 integration targets were then run explicitly: **476 passed,
  nine failed**. All nine failures reproduce on the baseline with the same first
  mismatch. This is not a claim of a green full-suite gate.
* External Unicode conformance/regeneration tests remain ignored. No corpus was
  downloaded and no snapshot was accepted to conceal an output difference.

### Baseline test corrections included with the migration

The existing frozen conversion fixture counted two outline widths as fresh
conversions although they are already exact quanta; the baseline also reports
38/35/16 rather than 40/37/16. The specialized producer fixture was too short to
force its asserted soft-hyphen break and omitted Heatmap's required owning color
scales. Its source now really wraps and its preparation receives those scales.

The seven broad-library failures covered old guide traces/work observations,
one-quantum guide enclosure, absent-outline canonical paint, and a shared-header
test that incorrectly required identical coordinates after swapping child themes.
The header test still verifies root-owned typography; child metrics legitimately
move span centers. Renderer defaults and production layout algorithms were not
changed to satisfy these stale expectations.

## Subsequent user-directed test policy

The user rejected fixed renderer-revision byte counts, hashes, pixel placements
and scene snapshots as volatile expectations. The current policy is in
`specs/90_DEVELOPMENT.md`; this is a test-contract change, not a renderer-output
repair or acceptance of new goldens.

* Removed whole-scene fingerprints for Waterfall, Beeswarm, Interaction and
  categorical-distribution marks.
* Retained Marginal's scientific-value, KDE, guide-content and linked-axis
  assertions while removing its stored SVG lengths/hashes and incidental spacing.
* Retained Matrix's actual observations/variable labels instead of its committed
  SVG hash/length, fixed adaptive-text count and external baseline comparison.
* Removed the visual-regression target, its 27 snapshots and unused `insta`
  dependency. The mixed Interaction fixture retains root containment, relative
  prose placement and explicitly requested PNG dimensions in its domain target.
* Heatmap's insufficient-space test keeps preflight/publication error agreement,
  the Render error category, no output on failure, and complete annotations when
  given sufficient space; it no longer fixes a particular internal error message.
* The native gutter fixture checks request/consumption relationships and final
  convergence instead of measured pixel coordinates from one revision.

All nine previously listed failures are thus either removed volatile-only checks
or migrated mixed fixtures whose meaningful assertions pass. The runtime renderer
was not changed. Historical release timing/output comparisons below remain
observations rather than permanent acceptance gates.

Twenty focused library tests and three migrated integration fixtures passed.
Removing the unused test dependency required one `just verify` under the
repository dependency-change rule: formatting, strict Clippy, **1,345 library
tests and 470 integration tests passed**, with 17 existing library tests ignored;
documentation and independently unpacked-package verification also passed.
The full gate log is `/tmp/opencode/semantic-tests-verify.log`. No snapshot was
repinned, no Unicode corpus was downloaded and no new test framework was added.

### Remaining interface cleanup

The follow-up removes accounting-era `Result` propagation from feedback/state
equality and the root's convergence/cycle predicates. Plain string, address,
request and miss comparisons use their existing equality; rendered-text identity
still compares complete effective style/provenance, lines, runs and glyphs while
excluding cached analysis. Real reservation, numerical and fit errors remain.
The remaining operation-ledger comments/instructions were corrected.

Strict Clippy and formatting passed, together with 45 focused kernel/feedback
and native-root tests and five representative layout, composition and output-reuse
integration checks. This localized follow-up did not repeat the full suite.

## Release output, elapsed time and RSS

The original complete 2,048-word fixture has now also been remeasured in
[the caption follow-up](caption-cleanup-performance.md), with independent
preserve/outline timings, full-source checks, scoped timing attribution and
fresh-process RSS. The nine-case publication study below retains its own boundary.

**Measured 2026-10-08:** `8c6e011` versus `75003b2` plus removal of the unused
benchmark admission CSV header. No renderer switch or experimental production
mode was introduced. Both use the same locked dependencies, local fonts and
existing `publication_efficiency_measurements` fixture in
`tests/benchmarks/suite.rs`. Host: Linux/WSL2
`6.18.33.2-microsoft-standard-WSL2`, x86_64; Rust 1.96.0
(`ac68faa20c58cbccd01ee7208bf3b6e93a7d7f96`), LLVM 22.1.2.

Four fresh processes ran sequentially in baseline-A, cleanup-A, cleanup-B,
baseline-B order, with compilation completed beforehand. Each process runs the
unchanged nine cases three times with no warmup: six samples per case/version.
These are optimized **test-build** measurements with existing semantic
observations enabled. Timing includes construction, real root preparation/font
discovery, layout, capture, outlined-SVG file publication and balanced source-size
PNG publication. File reads, SHA-256, PNG decoding and final Output destruction
are outside timing. The two ten-terminal cases retain their existing distinct
fresh-root versus reused-Output behavior.

All four runs passed their internal output/work stability checks. Across
versions, **all 27 hashes match**: outlined SVG, encoded PNG and decoded RGBA for
each of nine cases. Dimensions and byte lengths also match. The common hashes
are retained in [the output table](resource-accounting-cleanup-outputs.csv).

The ranges overlap. There is no demonstrated material RSS reduction in this

allocator profile was performed.

### Reproduction

In each checkout, compile the existing test executable with:

```sh
cargo test --locked --offline --release --lib publication_efficiency_measurements --no-run
```

Run the reported executable under `/usr/bin/time -f
'peak_rss_kib,%M\nelapsed_seconds,%e'`, passing:

```text
--exact orchestrator::tests::benchmarks::publication_efficiency_measurements --ignored --nocapture --test-threads=1
```

Only that existing release benchmark is explicitly enabled; Unicode corpus tests
remain ignored. Raw samples, lifecycle observations and hashes are preserved in
`/tmp/opencode/accounting-release-{baseline,cleanup}-{a,b}.log`; matching `.rss`
files contain process measurements. The session CSV reports summaries, not raw
per-render observations.
