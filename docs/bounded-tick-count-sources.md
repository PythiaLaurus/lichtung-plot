# Bounded Numeric Tick Count Sources

The common numeric source owner now implements the admitted target and hard
maximum semantics privately, through the existing immutable tick-selection
carrier and measured formatter/fit route. The current public API remains the
interval-only attachment until the following atomic generation-value cutover.

## Complete Sources

Targets select their requested initial adaptive seed and retain existing nice-step
ties and complete-list fit. The independent `[0,1]` witness requests four and
selects `[0,0.5,1]`; target five selects `[0,0.25,0.5,0.75,1]`. No exact-count
generator or scientific-domain edit is added.

A hard maximum filters the actual cardinality of complete automatic candidates.
Linear index counts and Forest integral/subset counts reject over-limit sources
before vector allocation. Formatting and metric lookup happen only for admitted
complete sources. The measured maximum-four witness crosses multiple over-limit
source attempts, formats exactly one list and measures its three labels; it
selects `[0,0.5,1]`. This is actual instrumentation, not a new accounting fee.
Adjacent finite domains cannot smuggle a two-endpoint vector through a maximum
of one. Target/maximum one use the original-domain midpoint, which must still fit.

Forest target four on `[-3,3]` starts with the four exponent positions
`[-3,-1,1,3]`, then the existing three/two-position subsets and midpoint. It does
not first admit all seven integral exponents. Maximum four retains Automatic's
ordered program but skips the seven/six/five-position candidates before storage.
Automatic's full-integral-first order, preferred additive/decade coarsenings,
unconfigured grammar, exact formatting, certified raw-power labels and original
midpoint scope remain intact.

The private count constructors admit `1..=10_000` and reject zero/over-limit input
before fonts. The common source bound references that same count constant. There
is no new root search, tick-label dropping, public cap or resource quota.

## Identity And Feedback

The same immutable carrier now contains the private count discriminants; it is
not accompanied by optional competing target/maximum fields. Existing complete
AxisSpec/composed copies therefore retain both values and their kind. The actual
composed-input contract proves a target five and maximum five cannot reuse one
another at equal width/domain, and that an unchanged retained choice still hits.

Axis semantic feedback delegates to the carrier. Existing Additive/Log10 tags and
payloads remain 1/2; private Target/Maximum use tags 3/4 plus the complete validated
integer. Absence remains the sole current Automatic representation. The old
two-case `expect` cannot reinterpret a count as a logarithmic interval.

The two private constructor methods have narrow non-test dead-code expectations
only for staging before public attachment. The generation API cutover must remove
both expectations while exposing the one replacement value; no public placeholder
or compatibility alias is added here.
